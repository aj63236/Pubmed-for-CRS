## 回補歷史文獻（不用裝任何東西）

在 GitHub 網頁上點按鈕就能跑，不需要 Mac、不需要 Python、不需要 git。

### 步驟

**1. Actions → 回補歷史文獻 → Run workflow**

會跳出四個欄位：

| 欄位 | 填什麼 |
|---|---|
| 起始日 | `2026-06-01` |
| 結束日 | 留空 = 到今天 |
| 每天最多抓幾篇 | `8`（想省錢就填小一點） |
| **試算模式** | **第一次務必勾選 ✅** |

**2. 先跑試算（不花錢）**

勾著「試算模式」跑一次。跑完點進 log，最後會看到：

```
要處理的日期：38 天
要抓的論文：  260 篇
  ├─ 需生成： 260 篇
  └─ 已快取： 0 篇
預估費用：    約 $9.10 USD
```

**3. 覺得可以接受，再跑一次，這次把「試算模式」取消勾選**

這次會真的呼叫 Claude，跑完自動 commit 並推上去，網站就有資料了。

38 天 × 8 篇大概要跑 30-50 分鐘，可以關掉瀏覽器，Actions 會在雲端繼續跑。

### 安全機制

- **試算模式預設是勾選的** —— 不會不小心花到錢
- **總量上限 400 篇** —— 日期填錯（例如填成 2020 年）會直接停下來，不會燒錢
- **快取** —— 中途失敗可以直接重跑，已處理的論文不會重複收費
- **已完成的日期會跳過** —— 重跑不會重做

## 選片機制

PubMed 每天有 **60-80 篇**符合條件的論文。流程：

1. **掃描當天全部**（跟 PubMed 拿資料**免費**）
2. **本機排序**（免費）：`分數 = 期刊 IF（上限 25，權重 0.5）+ 研究設計權重 × 2`
3. **選片**：分數最高的 **10 篇** ＋ **當天所有 Review**（上限 8 篇）
4. 只把選中的送去 Claude（這步才花錢）

### 為什麼研究設計壓過 IF

對外科醫師來說，**一篇 Dis Colon Rectum 的 RCT，比一篇 Lancet 的綜述有用**。所以設計權重（×2）刻意大於 IF 權重（×0.5，且上限 25）。

實測：DCR 的 RCT（25.9 分）勝過 Lancet 的綜述（14.5 分）。

### Review 為什麼另外撈

Review 的分數天生低（權重只有 1），純看分數會被高分 RCT 擠掉。但綜述對**跟上整個領域、準備專科考**很有用，所以獨立撈出來，不跟高分文章搶名額。

```python
MAX_RESULTS     = 10     # 高分文章幾篇
INCLUDE_REVIEWS = True   # 是否額外納入 Review
REVIEW_LIMIT    = 8      # Review 上限（避免暴量燒錢）
```

不想看 Review 就把 `INCLUDE_REVIEWS` 設成 `False`。

## 捲動與翻頁

**平常滑動 = 一般捲動。要換論文 = 按右側的 ▲▼。**

### 為什麼這樣改

原本用 `scroll-snap-type: mandatory`（強制吸附），但有**兩層互相打架的捲動容器**：

```
#feed          ← 外層，有強制吸附
  └─ .card
       └─ .body   ← 內層，也可以捲
```

手指往下滑 → 先捲內層 → 內層到底 → 動量「溢出」到外層 → 外層強制吸附。
iOS 的慣性捲動會帶著動量**一口氣跨過好幾張卡**才吸住 —— 這就是「突然跳很多」。

修法不是調參數，是**把巢狀捲動拆掉**：
- `.card` 從 `height:100dvh` 改成 `min-height:100dvh`（內容多就自然變高）
- `.body` 不再是獨立捲動容器
- 整個 feed 只剩**一層**捲動，`scroll-snap` 完全移除
- 卡片標題列改成 `position:sticky`，讀那一篇時一直黏在頂端

### 翻頁鈕

右側浮動，拇指可及。顯示「第幾篇／共幾篇」，到頭或到尾時箭頭自動變灰。

鍵盤（桌機）：`↑` `↓` 或 `k` `j`。

## 收錄時間

每篇論文會記錄**第一次被收錄進來的時間**，顯示在卡片底部：

```
🕐 收錄 今天 06:03            PMID 42425570
```

- 今天／昨天 → 顯示時分（`今天 06:03`）
- 一週內 → `3 天前`
- 一個月內 → `2 週前`
- 更早 → `6/15`

**重跑不會刷新時間** —— 收錄時間存在 `data/_cache_v3.json` 裡，
所以同一篇論文即使被重新處理，也會保留它「第一次進來」的時間。

### ⚠️ 順便修好的時區 bug

GitHub Actions 跑在 **UTC**。workflow 排在 `cron: 0 22 * * *`（UTC 22:00 = 台灣隔天 06:00）。
原本用 `datetime.now()` / `date.today()` 拿的是 UTC 時間，結果：

| | 修正前 | 修正後 |
|---|---|---|
| 檔案名 | `2026-07-12.json` ❌ 差一天 | `2026-07-13.json` ✅ |
| 時間戳 | `22:00` ❌ 差 8 小時 | `2026-07-13T06:00:00+08:00` ✅ |

現在所有時間都用台灣時區（UTC+8，無日光節約），並以帶時區的 ISO 格式儲存，
瀏覽器會自動轉成你所在時區顯示。

## 🔖 追蹤關鍵字（最重要的一個功能）

排序是用「期刊 IF + 研究設計」算分的。但**你最在意的東西不一定分數高**。

實例 —— 你在寫的 POUR 論文：

| 論文 | 期刊 | 分數 | 原本的下場 |
|---|---|---|---|
| 痔瘡切除術後尿滯留之危險因子 | Ann Coloproctol (IF 2.2) | **5.1** | ❌ 被丟掉 |
| 直腸 diclofenac 術後止痛 | Asian J Surg (IF 1.9) | **0.9** | ❌ 被丟掉 |

每天前 10 篇的門檻大概在 20 分以上。**跟你手上論文最相關的文獻，一篇都看不到。**
連你的目標期刊（Ann Coloproctol）正在發什麼，你也不會知道。

所以：**命中追蹤清單的論文，無視分數強制納入**，並標上 `🔖 追蹤`。

編輯 `watch.json`：

```json
{
  "limit": 6,
  "keywords": [
    "postoperative urinary retention",
    "hemorrhoidectomy",
    "haemorrhoidectomy",     ← 英美拼法都要放
    "diclofenac"
  ],
  "journals": [
    "Ann Coloproctol"        ← 目標期刊，看它們在發什麼
  ]
}
```

- `keywords` 比對「標題 + 摘要」，不分大小寫
- `journals` 比對期刊名
- `limit` 是每天上限（避免關鍵字太廣導致暴量燒錢）

## 🔗 與過去文獻的關係（資料庫比對）

過去收集的所有論文就是一個資料庫。每篇新論文進來時：

1. **本機用 TF-IDF 餘弦相似度**，從資料庫裡找出最相關的前作（免費，不呼叫 API）
2. **把那幾篇的標題與一句話結論一起餵給 Claude**
3. Claude 直接判定關係，並寫出比較

卡片上會出現：

```
與過去文獻   [與前作矛盾]

⚠️ 這篇的結論跟你之前看過的那篇（局部復發 4.2% vs 8.1%，
   有利機器手臂）直接矛盾。兩篇都是多中心 RCT，但這篇樣本數
   較大（n=1,140 vs 486）且發表在較高分期刊。在有統合分析之
   前，機器手臂降低局部復發的說法應該保留。

你之前看過的相關論文
  [8] 機器手臂與腹腔鏡 TME 五年成果        7月10日   ← 點了直接跳過去
```

四種判定：

| 判定 | 顏色 | 意思 |
|---|---|---|
| **與前作矛盾** | 🔴 紅 | 最該注意 —— 結論打架了 |
| **延伸前作** | 🔵 藍 | 補上了之前缺的那一塊 |
| **再確認** | 🟢 綠 | 又一篇講同樣的事 |
| **無相關前作** | ⚪ 灰 | 這個主題的第一篇（整個區塊不顯示） |

### ⚠️ 防止硬掰關聯

相似度門檻設 **0.15**。原本設 0.10 時，兩篇只因為都提到 *colorectal cancer*
就會被配在一起（餘弦 0.11）—— 那種假關聯餵給模型很危險，它會硬生出一段
不存在的「關係」。

Prompt 裡也明確要求：**若列出的前作其實跟本篇無關，就誠實填「無相關前作」，不要硬掰。**

實測：一篇維他命 D 與骨密度的論文丟進大腸直腸科的資料庫 → 正確回報「無相關前作」。

每篇多約 **$0.003**（每月多不到 $1）。

## 卡片顏色 = 訊息，不是裝飾

之前是六種馬卡龍色「輪流換」—— 顏色由**第幾張卡**決定，跟內容毫無關係。那是噪音。

現在顏色直接回答一個問題：**這篇我該不該花時間？**

| 顏色 | 層級 | 什麼情況 |
|---|---|---|
| 🌹 **玫瑰** `#FFE2EC` | **必讀** | 追蹤命中 / 跟你已知的矛盾 / 高分又高度相關 / 可能改變實務 |
| 🩵 **天藍** `#E7F2FB` | 相關 | 一般該讀的 |
| ⬜ **灰** `#F2F1F3` | 可略過 | 低度相關或低分 —— 飽和度 0.8%，視覺上刻意「退後」 |

必讀的卡片還多一道**玫瑰色左邊界**，滑過去很難錯過，並標上 `★ 必讀`（滑鼠移上去會說明**為什麼**）。

### 為什麼這樣分

最能說明價值的例子 —— 你的 POUR 論文：

```
🌹 必讀   痔瘡切除術後尿滯留之危險因子    評分 5/10   中度相關
          └─ 命中追蹤：hemorrhoidectomy、urinary retention
```

**只有 5 分、中度相關。** 純看分數它是一張平庸的中間卡，你會滑過去。
但那是**你正在寫的論文的題目** —— 所以它是玫瑰色。

### 兩個軸不衝突

- **評分 chip** 的紅綠燈（綠/琥珀/紅）→ 這篇的**品質**
- **卡片底色**（玫瑰/天藍/灰）→ 這篇跟**你**的相關程度

一篇論文可以是「低分但必讀」（你的追蹤主題），也可以是「高分但可略過」（跟你無關的領域）。

搜尋結果、收藏清單用**同一套顏色語言**，不會自相矛盾。

## 費用與模型

預設用 **claude-sonnet-5**（8/31 前促銷價 $2/$10，比 Sonnet 4.6 便宜且更新）。

| 用量 | 費用 |
|---|---|
| 每天 12 篇 | 約 **$8/月** |
| 每天 6 篇 | 約 **$4/月** |
| 回補 6/1 至今（約 260 篇） | 一次性約 **$6** |

PubMed API 免費。建議 console.anthropic.com → Billing 設 $20 月上限。

⚠️ **9/1 起 Sonnet 5 漲回 $3/$15**，屆時費用會變成約 $12/月。

### 想換模型

Settings → Secrets and variables → Actions → **Variables** 分頁 → New variable
- Name: `MODEL`
- Value: 下面其中一個

| 模型 | 每月(12篇/天) | 說明 |
|---|---|---|
| `claude-sonnet-5` | $8 | **預設**。促銷中 |
| `claude-haiku-4-5-20251001` | $4 | 便宜 3 倍，但**批判性分析與 NNT 計算會變差** |
| `claude-opus-4-8` | $21 | 最強，但貴一倍 |

### 關於「換 OpenAI 會不會比較便宜」

**不會。** 同層級的旗艦模型價格幾乎一樣：

| | 每月(12篇/天) |
|---|---|
| Claude Sonnet 4.6 | $12.42 |
| gpt-5.4 / gpt-5.6-terra | $12.06 |

一個月差 $0.36。OpenAI 那些超便宜的價格（mini / nano）是**小型模型**，不是同一個等級；而 Anthropic 也有小型模型（Haiku 4.5 $1/$5，比 gpt-5.6-luna 的 $1/$6 還便宜）。

**真正的問題不是「換哪家」，是「要不要用小模型」——那是品質問題，不是廠商問題。**

### 想省錢，先動這個

把 `fetch_papers.py` 的 `MAX_RESULTS` 從 12 調到 **6-8**。費用直接砍半，而且**完全沒有品質損失**——你只是每天少看幾篇，反正大部分日子也沒有 12 篇值得讀。

這比換小模型安全得多。

**網站沒更新** → 按右下角「更新」，或 Ctrl+Shift+R。
